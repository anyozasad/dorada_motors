DORADA MOTORS — GUÍA PARA LA DEMOSTRACIÓN DEL PROFESOR

Proyecto: aplicación Flutter + API PHP + Dashboard PHP + MySQL.
Empresa del caso: ADN Import's / Dorada Motors.

1. INICIO RÁPIDO EN WINDOWS
- Abrir XAMPP y encender Apache y MySQL.
- Abrir PowerShell en la carpeta dorada_motors, donde está pubspec.yaml.
- Ejecutar:
    git pull origin main
    powershell -ExecutionPolicy Bypass -File .\INICIAR_DEMO.ps1
- El script copia PHP y las imágenes a C:\xampp\htdocs\dorada_api e inicia Flutter en Chrome.

2. DIRECCIONES
Flutter: http://localhost:8080
Panel PHP: http://localhost/dorada_api/admin_login.php
Catálogo API: http://localhost/dorada_api/productos.php
phpMyAdmin: http://localhost/phpmyadmin/

3. QUÉ PRESENTAR
A) En PHP:
   - Iniciar sesión administrativa.
   - Mostrar productos, marcas, categorías, clientes, pedidos, pagos, proveedores,
     compras, inventario, movimientos de stock, comprobantes y reportes.
   - Editar un producto y guardar sus cambios.
   - Consultar y atender solicitudes de soporte del cliente.
   - Registrar compras a proveedores, ajustar inventario y comprobar Kardex.
B) En Flutter:
   - Mostrar acceso, registro, catálogo, búsqueda y filtros.
   - Ver el producto editado en PHP.
   - Iniciar sesión como cliente, editar perfil, direcciones, favoritos y carrito.
   - Realizar un pedido seleccionando una dirección guardada.
   - Consultar el historial de compras.
   - Enviar una solicitud de soporte desde Flutter y responderla en PHP.
   - Probar «Olvidé mi contraseña»: registro en soporte y restablecimiento solo tras verificar identidad.
C) En MySQL:
   - Mostrar que los pedidos y el detalle se guardaron realmente.
   - Verificar que el stock disminuyó y quedó registrado el movimiento.
   - Mostrar que el pago queda pendiente hasta ser confirmado en administración.

4. BASE DE DATOS
El esquema principal es dorada_motors.sql e incluye 18 tablas:
usuario, sesion_cliente, direccion, categoria, marca, producto, pedido,
detalle_pedido, pago, proveedor, compra, detalle_compra, movimiento_stock,
comprobante, carrito, detalle_carrito, favorito y solicitud_soporte.

Si el inventario está vacío al instalar la base, se agregan 19 artículos de
demostración y sus imágenes. No se sobrescribe inventario ya existente.

5. SEGURIDAD
Los clientes reciben un token que se envía con cada operación privada.
La recuperación asistida no envía correos automáticos: el administrador verifica identidad, asigna una clave temporal por un canal seguro y se revocan sesiones anteriores.
El servidor valida que el pedido, las direcciones, el carrito y los favoritos
pertenezcan a la cuenta autenticada. El panel PHP tiene roles y protección CSRF.

6. VALIDACIÓN EN CADA COMPUTADORA
flutter pub get
flutter analyze
flutter test
flutter run -d chrome --web-port 8080

Para revisar PHP:
C:\xampp\php\php.exe -l C:\xampp\htdocs\dorada_api\dashboard.php

OBSERVACIONES
- La aplicación requiere Apache y MySQL para guardar información en la base.
- Los datos locales de Flutter ayudan con el respaldo de la interfaz, pero
  los pedidos confirmados se envían al servidor.
- Yape/Plin son opciones de pago registradas, no cobros reales automáticos.
- Los comprobantes de la demo no sustituyen un comprobante electrónico SUNAT.
- Consultar MATRIZ_VALIDACION_FUNCIONAL_150.md para verificar los 150 requisitos.
- Ejecutar desde la carpeta principal: powershell -ExecutionPolicy Bypass -File .\\VERIFICAR_SISTEMA.ps1
- El funcionamiento definitivo debe verificarse en la PC del profesor.
